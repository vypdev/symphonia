## Final authorization and fixture-boundary follow-up

A denial received at or after the authorization attempt deadline now follows
consumption's expiry rule inside the same SQLite write transaction: persist
`expired`, commit that outcome, and reject the late denial. A subsequent callback
cannot replace the expired or previously consumed result. An unexpired denial
keeps its existing terminal behavior. No schema, provider token handling, or
callback topology is added.

The isolated Lit spike checks window member expressions in its already parsed
TypeScript AST. Dot, computed string/template, escaped, optional and global
window/self forms cannot access the parent window; unresolved computed window
members are rejected conservatively. Ordinary local window properties remain
available. This source guard is narrow architecture evidence for trusted fixture
code, not an arbitrary-JavaScript sandbox or a production host-context adapter.

The additional regression budget is **14 distinct inputs**: four authorization
state scenarios (exact deadline, late denial, expiry replay, consumed-state
preservation) and ten fixture syntax/control inputs. The callback service also
exercises the expiry rule through its public entrypoint. Both reported defects
were reproduced against the unchanged implementation before the correction.
The full Python suite and coverage, spike types/tests/boundary/build/output,
specification consistency and current-head GitHub review remain merge gates.
